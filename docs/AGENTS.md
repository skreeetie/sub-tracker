# AGENTS.md — инструкции для агента

Проект **sub-tracker** — fullstack-приложение для учёта подписок.

## Стек

| Слой | Технология |
|---|---|
| Фреймворк | Next.js 16 (App Router), React 19 |
| Язык | TypeScript (`strict: true`) |
| Стили | Tailwind CSS v4 (через `@tailwindcss/turbopack`) |
| База данных | PostgreSQL в облаке Neon, подключена через Vercel (драйвер `postgres`) |
| Хостинг | Vercel |
| ORM | Drizzle ORM + drizzle-kit (миграции) |
| Валидация | Zod |
| Графики | Recharts |
| Тесты | Unit-тесты (Vitest) |
| Линтер | ESLint 9 (`eslint-config-next`) |
| Рантайм | Node.js 26 (через fnm) |
| Пакетный менеджер | **pnpm** (npm/yarn не использовать) |
| Архитектура | **Feature-Sliced Design (FSD)** — подробности в `docs/ARCHITECTURE.md` |

> **Next.js 16 отличается от того, что ты знаешь.** API, соглашения и структура файлов могли измениться (например, `middleware.ts` переименован в `proxy.ts`). Перед написанием кода читай соответствующий раздел в `node_modules/next/dist/docs/` и учитывай deprecation-предупреждения.

## Команды

| Команда | Что делает |
|---|---|
| `pnpm install` | Установить зависимости |
| `pnpm dev` | Dev-сервер на http://localhost:3000 |
| `pnpm build` | Production-сборка (включает проверку типов) |
| `pnpm start` | Запуск production-сборки |
| `pnpm lint` | ESLint |
| `pnpm lint:fsd` | Проверка правил FSD (steiger, конфиг — `steiger.config.mts`; слой `views` не проверяется) |
| `pnpm test` | Unit-тесты (Vitest, один прогон) |
| `pnpm test:watch` | Unit-тесты в watch-режиме |
| `pnpm db:generate` | Сгенерировать миграцию по изменениям схемы *(этап 4)* |
| `pnpm db:migrate` | Применить миграции к базе *(этап 4)* |
| `pnpm db:seed` | Создать демо-пользователя, повторный запуск безопасен *(этап 4)* |
| `pnpm db:studio` | Drizzle Studio — веб-просмотр базы *(этап 4)* |

Тесты — файлы `src/**/*.test.ts` рядом с тестируемым кодом, конфиг — `vitest.config.ts` (алиас `@/*` → `src/*`).

Переменные окружения — в `.env` (шаблон — `.env.example`):
- `DATABASE_URL` — pooled-подключение к Neon, использует приложение;
- `DATABASE_URL_UNPOOLED` — прямое подключение, используют миграции и сид.

Локальный `.env` указывает на ветку `dev` в Neon, production — на основную ветку.

Никогда не выводи значения этих переменных в лог, чат или код.

Установку postinstall-скриптов зависимостей pnpm разрешает явно, через `allowBuilds` в `pnpm-workspace.yaml`.

Список будет дополняться (миграции, сиды, БД) по мере прохождения этапов `PLAN.md`.

## Деплой

- Хостинг — Vercel: https://sub-tracker-iota.vercel.app
- **Пуш в `main` сразу уходит в production.** Пушить в `main` только то, что прошло `pnpm lint`, `pnpm lint:fsd`, `pnpm test` и `pnpm build`.
- Остальные ветки и PR получают preview-деплои.
- Переменные окружения production (`DATABASE_URL`, `DATABASE_URL_UNPOOLED`) задаются в Vercel, не в репозитории.
- Миграции к production-базе применяются вручную и только после согласования с пользователем — в сборку Vercel они не встроены.

## Правила работы

1. **Перед началом любой работы** прочитай `docs/SPEC.md` и `docs/PLAN.md` (а при работе со структурой/данными — `docs/ARCHITECTURE.md`).
2. **За один раз выполняется только один этап** из `PLAN.md`. Закончил этап — остановись и отчитайся, следующий не начинай без команды.
3. **Тесты — на усмотрение агента.** На текущем этапе достаточно unit-тестов (Vitest). Приоритет — чистая бизнес-логика (расчёт дат продления, агрегации трат, валидация).
4. **Если для фичи написаны тесты — работа не продолжается, пока все тесты не зелёные.**
5. **Выполненные пункты в `PLAN.md` отмечай** (`- [ ]` → `- [x]`).
6. **Не добавляй фичи и зависимости, которых нет в `SPEC.md` / `ARCHITECTURE.md`, без согласования** с пользователем.
7. **Секреты и ключи — только через `.env`.** В репозиторий коммитится только `.env.example` с пустыми/фиктивными значениями.
8. **Файлы `docs/AGENTS.md`, `docs/SPEC.md`, `docs/PLAN.md`, `docs/ARCHITECTURE.md` меняются только после согласования** с пользователем. Исключение — отметки о выполнении пунктов в `PLAN.md`.
9. Соблюдай правила импортов FSD: слой может импортировать только из нижележащих слоёв, слайсы одного слоя друг друга не импортируют, импорт из слайса — только через его публичный API (`index.ts`).

## Запреты

- ❌ **Не использовать `any`** (ни явно, ни через `as any`). Если тип неизвестен — `unknown` + сужение типа.
- ❌ **Не менять схему БД без миграций.** Любое изменение схемы = новая миграция в репозитории; ручные правки БД и `db push` в обход миграций запрещены.
