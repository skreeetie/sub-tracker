- [x] Обновить раздел «Команды» в `AGENTS.md`.

**Готово, когда:** проект очищен от шаблона, `pnpm dev` запускается и показывает пустую стартовую страницу, `pnpm test` проходит, `pnpm lint` и `pnpm build` без ошибок.

## Этап 3. Подключение базы данных

- [ ] Локальный PostgreSQL (способ установки без Docker согласовать с пользователем), `DATABASE_URL` в `.env` и `.env.example`.
- [ ] Валидация переменных окружения в `shared/config/env.ts` (Zod).
- [ ] Установить `drizzle-orm`, драйвер Postgres, `drizzle-kit`; `drizzle.config.ts`.
- [ ] Клиент БД в `shared/db` (только серверный код, `server-only`).
- [ ] Схема таблицы `users`, первая миграция.
- [ ] Сид: тестовый пользователь (демо-аккаунт).
- [ ] Скрипты `db:generate`, `db:migrate`, `db:seed` (+ `db:studio` по желанию), обновить «Команды» в `AGENTS.md`.

**Готово, когда:** `pnpm db:migrate` и `pnpm db:seed` на чистой БД отрабатывают без ошибок, в таблице `users` есть демо-пользователь; `pnpm build` без ошибок.

## Этап 4. Личный кабинет (моковая авторизация)

- [ ] `entities/user`: тип пользователя, запрос пользователя по id.
- [ ] `entities/session`: получение текущего пользователя из cookie (`getCurrentUser()` / `requireUser()`).
- [ ] `features/auth`: кнопка «Войти» (server action — устанавливает cookie демо-пользователя и редиректит в кабинет) и кнопка «Выйти» (удаляет cookie, редирект на стартовую).
- [ ] Защита страниц кабинета: гость → редирект на стартовую страницу.
- [ ] Имя пользователя и «Выйти» в шапке, страница профиля.

**Готово, когда:** «Войти» открывает кабинет под тестовым аккаунтом, «Выйти» возвращает на стартовую, прямой переход на страницы кабинета без входа редиректит на стартовую; `pnpm build` без ошибок.

## Этап 5. Добавление подписок

- [ ] Схема таблицы `subscriptions` (+ enum'ы периода и категории) и миграция.
- [ ] `entities/subscription`: типы, константы категорий и периодов, функция расчёта следующей даты списания (+ unit-тесты, включая конец месяца и високосный год).
- [ ] Zod-схема валидации подписки (+ unit-тесты).
- [ ] `features/create-subscription`: форма (название сервиса, стоимость, период ежемесячно/ежегодно, дата начала, категория) + server action с серверной валидацией.
- [ ] Страница «Подписки»: список подписок текущего пользователя + пустое состояние.

**Готово, когда:** пользователь может добавить подписку, она сохраняется в БД и отображается в списке с датой следующего списания; невалидные данные не сохраняются и показывают ошибки; тесты зелёные, `pnpm build` без ошибок.
